Git Basics — The Time Machine

📖 Reading time: 30 minutes 🎯 Difficulty: Beginner (but this is a SUPERPOWER)

Why Does Git Exist?

Imagine deleting todo-app.html by accident. Press Ctrl+Z... nothing happens. Your work is gone. Forever.

In 2005, the Linux operating system (which runs most of the world's servers) lost its free version-control tool. Linus Torvalds got angry, locked himself in a room, and wrote a replacement in about 10 days. That tool is Git.

💡 Definition:

Version Control System (VCS) — software that records snapshots of your files over time, so you can rewind, compare, and collaborate safely.

Analogy: Git is a save-point system in a video game — but for every file, forever. Even better: you can create a parallel universe (a branch) to try something risky, and delete it if it fails.

Every company on Earth uses it: Google, Netflix, Microsoft. A resume without Git gets rejected instantly. This is not optional knowledge — it IS the job.

The Three Rooms (Core Mental Model)

Most beginners fail Git because they never build this picture. Memorize it:

YOUR FOLDER THE WAREHOUSE THE SAFE VAULT ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ │ Working Dir │ --> │ Staging │ --> │ Repository │ │ (files you │ add │ Area │commit│ (.git folder) │ │ edit daily) │ │ ("cart") │ │ = safe vault │ └──────────────┘ └──────────────┘ └──────────────┘ "store" "shopping "pay and take cart" it home"
  • Working Directory — your folder, exactly what you see in VS Code
  • Staging Area — a shopping cart: you choose which changes go into the next snapshot
  • Repository — the permanent, time-stamped vault (a hidden folder called .git)
✅ Key Word: commit

A commit = one named snapshot + a message explaining WHY. Senior engineers treat commits like sentences in a story. Future-you and code reviewers will read them.

Step 1 — Setup (once per machine)

Open the VS Code terminal with Ctrl+` (Ctrl + backtick). Then:

📄 One-time configuration
# "pwd" = print working directory. Always know WHERE you are before acting.
pwd

# "git init" = initialize a repository here. Creates the hidden .git vault.
git init

# Tell Git who you are. Required! Every commit is signed with this name.
# --global is a "flag": it means "apply this setting everywhere on my machine".
git config --global user.name "Your Name"
git config --global user.email "your@email.com"

Step 2 — The Daily Workflow

📄 The 4 commands you'll type 10,000 times
# 1. What does Git see right now? READ THIS EVERY TIME. Red = not staged, green = staged.
git status

# 2. "git add ." = put EVERYTHING in the current folder (the "." means "all of here")
#    into the shopping cart. To stage one file only: git add README.md
git add .

# 3. "commit" = pay for the cart. -m stands for "message" (a flag).
#    Present tense, imperative mood: "Add", "Fix" — never "Added" or "update".
git commit -m "Initial commit: course lessons + 5 beginner projects"

# 4. "log" = view your time machine's dashboard. --oneline compresses history to one line per snapshot.
git log --oneline
🤔 Think like an engineer:

Why doesn't Git just commit everything automatically? Answer: sometimes you have junk files, secrets, or half-finished experiments in your folder. The staging area is a checkpoint where you decide what becomes history. Professional habit: always run git status BEFORE git add.

Commit Messages — Writing Like a Professional

📄 Bad vs Good
# ❌ BAD - tells future-you nothing
git commit -m "update"
git commit -m "fix"
git commit -m "stuff"

# ✅ GOOD - tells a story
git commit -m "Add filter buttons to todo app"
git commit -m "Fix clock showing 13:00 instead of 1:00 PM"
git commit -m "Refactor weather fetch into separate function"

# ✅ PROFESSIONAL (Conventional Commits - used by real teams)
git commit -m "feat: add dark mode toggle"
git commit -m "fix: prevent XSS in todo rendering"

The prefixes feat:, fix:, docs:, refactor: follow the Conventional Commits standard — tools at real companies auto-generate changelogs from them.

Common Beginner Errors (feel them on purpose)

Error messageWhy it happenedFix
fatal: not a git repository You ran a git command in a folder where no vault exists (or a subfolder) Run git init or check pwd
Please tell me who you are user.name / user.email not configured Run the two config commands from Step 1
nothing added to commit You ran commit without add — the cart was empty git add . first
"I lost my commit!" You almost never lose commits in Git — that's the whole point git log --oneline to find it, git reflog for the "vault of the vault"

Practice

  • Easy: Create NOTES.md, write one line, commit it: "Add study notes"
  • Medium: Edit README.md (add one line), then run git diff — explain what the + and - colors mean
  • Hard: Make 3 quick commits, then read git log --oneline — write the "story" your project now tells

🤔 Did You Know?

Torvalds named it "git" — British slang for a stupid, obnoxious person. His words: "I'm an egotistical bastard, so I name all my projects after myself: Linux, git..." The most important tool in software history was named as a self-insult.
